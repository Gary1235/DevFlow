# DevFlow

本機 AI 開發工作台：需求討論、規劃、隔離實作、AI／人工驗收與本地 Git 合併。

在專案根目錄執行 `npm run dev`，會一起啟動網頁（5173）、API（5180）與 Worker。首次使用先在 `frontend` 執行 `npm ci`；根目錄啟動器沒有額外 npm 套件。需要 .NET 10 SDK、Node.js 與已安裝的 AI CLI。

啟動器會沿用 `backend/src/DevFlow.Api/.data/devflow.db`，保留既有任務；API 與 Worker 共用資料庫、執行紀錄、工作副本與 CLI 控制目錄。桌面版繼續使用自己的資料。按 Ctrl+C 會停止本次啟動的服務；已在執行且資料庫相同的服務會沿用，不會被關閉。紀錄位於資料庫旁的 `dev-logs`。

只啟動後端可用 `npm run dev:backend`。若啟動器發現佔用埠的是舊版 API 或不同資料庫，會停止並提示先關閉舊開發服務，不會自動合併或覆蓋資料。

Windows 開發版可用 `npm run dev -- --notify` 啟動系統匣核准通知，網頁關閉後仍會提示，直到啟動器結束。專案設定新增目標偵測、工具版本預檢與隔離副本測試；合併視窗可建立分歧整合任務，失敗實作可預覽未提交檔案並建立恢復任務。Codex 預設提供主程序結構化檔案／驗證工具，減少 shell 無法解析造成的確認；仍遵守政策與修改範圍。操作、相容性及限制見 [第二輪改善紀錄](docs/audit-round-two.md)。

設定測試結果會保存到資料庫，可在專案設定「載入最近設定測試」重新檢視、追蹤或取消。API 異常中斷後會標示中斷並保留副本，不自動重跑；詳細行為見 [第三輪改善紀錄](docs/audit-round-three.md)。

- [Windows Electron 桌面版](desktop/README.md)：一鍵啟動、系統匣背景執行、任務通知、安裝包建置。
- [React 工作台](frontend/README.md)：網頁開發模式與功能操作。
- [.NET API／Worker](backend/README.md)：執行流程、CLI 設定、資料與 API。

任務驗證與本地驗收：在「專案 → 專案設定」建立驗證設定與預覽服務，再在流程步驟選擇驗證設定。工作目錄使用專案內相對路徑；執行程式與參數分開填寫，每行一個參數。例如後端工作目錄 `backend`、程式 `dotnet`、參數 `test` 與 `CHR.sln`；前端工作目錄 `frontend`、程式 `npm`、參數 `run` 與 `build`。新工作副本沒有 npm 套件時，可勾選依賴準備並填 `ci`（需 lockfile），會在驗證前執行。一般指令以退出碼判斷，不會假裝產生測試數量；TDD 仍需要 DotnetTest 逐項結果。未設定的既有專案沿用原 dotnet test 參數。

成果審核頁提供「啟動預覽」「開啟網站」「停止預覽」與日誌。預覽服務的埠填 `0` 自動分配，啟動參數或環境變數必須使用 `{port}`；可用 `{port:其他服務ID}` 串接前後端，並把後端排在前端前面。只有成果提交、工作副本與分支一致、且任務已結束或暫停時可啟動。預覽會鎖定工作副本；停止後解除鎖定，API 正常關閉也會停止其預覽程序。Windows 另以 Job Object 管理子程序。關閉網頁分頁不會停止預覽。資料庫不會自動複製或隔離，須自行填入測試連線；網頁開啟的是 API 所在電腦的本機服務。預覽與驗證設定不會修改手動 CLI 的權限設定。

桌面第一版支援 Windows x64，保留現有前後端架構；AI 呼叫仍由本機官方 CLI 執行。

AI 工作預設不設總執行期限：Antigravity 使用 `--print-timeout 0`，Worker 的 `DevFlow__ExecutionTimeoutSeconds` 預設為 `0`（不限制），討論也不因固定時間自動停止。仍可手動取消，服務關閉會中止執行。若自行設定正數的 Worker 期限，仍依該秒數中止；連線測試、登入與專案驗證指令維持各自期限。`git grep` 已支援一般工作副本內容搜尋（包含 `-i`、`-n`、`-l`、`-e` 與前後文參數），歷史參照、外部路徑、未知參數及外部工具擴充仍需確認。

工具確認以 CLI 生命週期為準：DevFlow 不設兩分鐘拒絕期限，兩分鐘後只在確認卡提醒；不會自動核准或拒絕。CLI 退出、確認通道斷線或使用者停止執行，請求才會失效。Antigravity 暫存 hook 不覆寫 CLI 原生 timeout，若 CLI 自身中斷會直接回報，不能保證每個 CLI 都無限等待。已結束的 CLI 不會因網頁再次點擊而恢復或重新執行。

2026-10-23 的流程改善：工作台頂端提供跨任務／討論的工具待確認清單，可自行啟用瀏覽器通知與提示音；切回網頁會立即更新。網頁開啟期間會在背景嘗試讀取，但瀏覽器休眠或關閉分頁後不能保證通知；桌面版由背景主程序讀取待確認清單。Worker 預設可同時執行兩個獨立 repository 的任務，同一 repository 依序執行；可用 `DevFlow__MaxConcurrentTasks=1`～`4` 調整，同時會增加 AI 使用量。

Baseline 通過後，一般實作／Green／Refactor 的驗證失敗會將錯誤交回 AI，最多修正兩次；相同錯誤重複出現即停止。Baseline、Red、依賴準備失敗、逾時與 CLI／權限拒絕不進入這個修正循環。修正日誌保留在獨立 Attempt 目錄；npm ci 在同一次 Run、同一 worktree 且設定／lockfile 未變更時可重用準備結果。

新的開發版預設 worktree 目錄為原始碼旁的 `<DevFlow 路徑>.worktrees`，可讓 DevFlow 管理自身；既有任務保留原始路徑，不會搬移檔案。若需繼續以原目錄管理舊副本的預覽／清理，可設定 `DevFlow__WorktreeRoot`。啟動器預設建置 Release；測試可用 `DEVFLOW_BUILD_CONFIGURATION=Debug`。完整建置後執行 `npm run test:runtime` 可驗證真實 API／Worker 啟停，不呼叫 AI。

工具權限：在「工具權限設定 → 全域自動化政策」管理所有專案與 CLI 共用的指令、連線資源路徑、目的地及核准下載網域。啟用時，指定任務工作副本內檔案的讀取、搜尋、新增、修改與單檔刪除預設允許，不依檔名、副檔名或舊的敏感路徑名單攔截；包含 .env、憑證、資料庫檔及 input-password 元件。開發者須先隔離真正機密並使用測試資料；Git worktree 不是作業系統沙箱。討論、規劃及 AI 審查維持唯讀，任務／步驟的修改範圍仍有效。工作副本外存取、符號連結、Git／代理權限設定修改、目錄／遞迴刪除、未知腳本、上傳及未核准外連保留確認。資料庫指令與部署不因操作資料夾位於專案內而放行。舊敏感路徑設定保留為連線資源路徑限制，不影響副本內檔案。簡單本機 GET 與已核准網域的無憑證 HTTPS GET 可自動允許，不等於授權套件安裝或執行腳本。關閉自動化政策時使用舊的一般讀取規則。設定變更只影響後續請求，待確認項目仍須回覆。

一般內容搜尋依「操作與實際讀取範圍」判斷：`rg`、CLI 的檔案搜尋工具與 `Get-ChildItem | Select-String` 共用工作副本邊界檢查；自動化模式不強制搜尋管線包含 `-File` 或副檔名篩選。`Select-Object -First` 不縮小邊界檢查範圍。連結、無法讀取的目錄或超過 20,000 項檢查上限時改為確認，可縮小搜尋範圍。系統不改寫原指令，也不會只因指令在專案目錄執行，就允許未知腳本或參數。

自動化檔案操作使用共用的操作／目標解析，不再套用舊的一般讀取格式白名單。PowerShell 的 `-Path a,b`、`-LiteralPath 'a','b'`、含空白或逗號的引號路徑及目錄萬用字元會展開並逐一驗證；讀取、搜尋、雜湊與檔案修改使用同一工作副本邊界。複製／移動會檢查來源與實際目的檔案；管線輸出到副本內檔案屬於寫入，仍遵守唯讀階段與修改範圍。大量刪除、腳本執行、連線與權限設定修改保留授權；若動態語法或參數副作用無法確認，回報「無法確認操作邊界」，不會僅因工作目錄在專案內就自動執行。

內建檔案指令須比對完整名稱，`Get-Content.exe` 等任意程式不繼承讀取權限。Windows 常用別名會先轉為相同操作再比對自訂指令限制；沒有額外限制時，一般副本內讀取與寫入仍放行。讀取分隔符、位元組輸出與檔名篩選不另行要求授權。原生 CLI 的檔案變更若一次包含多筆刪除，與命令列多檔刪除一樣需要確認；單檔複製到既有目錄則檢查實際目的檔案，不視為複製整個目錄。

Shell 語意由 CLI 轉接層標記：Claude `Bash` 不套用 PowerShell 別名；無法證實 Shell 的原生請求不自動授權 PowerShell 專屬操作。Shell 不明時，一般 Git／rg 查詢仍按各自語法檢查，無法確認的操作交由人工授權。讀取編碼交由實際 cmdlet 驗證，`LiteralPath` 中的方括號視為檔名。遞迴搜尋搭配檔名萬用字元時，先檢查整個搜尋根目錄內的連結；即使根目錄沒有符合項目，也不漏掉深層目錄連接。CLI 轉接層的唯讀檢查使用共用操作判斷，不再依搜尋文字中的 delete 等關鍵字直接拒絕。

同一次指令請求會合併計算串接與管線各階段的刪除數量，多筆刪除仍需確認；紀錄保留刪除／寫入分類，不會因串接而標成一般讀取。明確檔名中的 `~`（例如 `app~old.cs`）與複製目的檔名的方括號可正常通過副本邊界檢查；家目錄展開、越界路徑及修改範圍限制仍保留。

`.gemini` 與其他 CLI 的代理設定目錄一致：副本內讀取自動允許，寫入、刪除或移入設定需確認。Git 搜尋允許普通檔名中間的 `~` 與逗號，仍保留 Git pathspec 特殊語法、萬用字元與越界路徑的確認。

原生檔名搜尋同時檢查搜尋目錄與 glob 模式；一般相對路徑、檔名字元集合及明確的大括號選項可自動判斷，上層跳轉、絕對路徑、無法確認的模式及搜尋樹內連結保留確認。搜尋模式使用 `/` 分隔路徑，避免反斜線跳脫歧義。內容搜尋的正規表示式不套用檔名模式判斷。Claude `Glob`／`Grep` 省略目錄時，會在實際 CLI 輸入中補入本次工作副本；Gemini 使用明確的 `dir_path`，省略目錄可能涉及多個工作目錄，仍保留確認。

代理控制檔 `.mcp.json`、`AGENTS.override.md`、`CLAUDE.local.md` 與既有代理設定同樣保留修改／刪除確認，讀取仍自動允許。實作階段的 AI CLI 可共用專案已儲存的驗證指令：必須是相同執行程式、完整參數與副本內工作目錄的獨立指令；紀錄包含命中的驗證 ID 與專案版本。規劃／討論、套件安裝、依賴準備、預覽指令、參數變更、串接與額外 CLI 權限不會因此放行；明確的敏感指令設定優先。設定修改或移除會影響之後的工具請求，既有已開始的程序不會被撤回。

PowerShell 內容搜尋支援 `Select-String -Path (Get-ChildItem ...).FullName -Pattern ...`，會以共用解析器檢查檔案列舉、搜尋參數與後續管線，並保留完整來源的副本／連結邊界及自訂指令限制。其他括號運算、方法呼叫、巢狀腳本與未知來源仍需確認；若傳回的檔名包含會被 `-Path` 再次展開的字元，需改用 `-LiteralPath`。此支援只適用於已確認的 PowerShell 與啟用自動化的模式。

這是對 CLI 提交給 DevFlow 的工具請求進行判斷，不是作業系統沙箱；CLI 內部未提出確認的操作與腳本間接存取不保證被攔截。保留各 CLI 原生限制，不開啟全域跳過確認。專案設定內的 Worker 驗證／預覽程式由使用者指定，請使用測試資料與連線。
