# DevFlow v0.7 React 開發工作台

## CLI 版本管理

在「AI 連線」各張 CLI 卡片下方按「檢查 CLI 更新」，查看目前版本、npm 最新版本與實際執行檔。
版本查詢只在點擊時連線至官方 npm registry，不呼叫模型、不自動安裝。
若有新版且 DevFlow 能確認目前 CLI 屬於可管理的 npm 全域安裝，可按「更新 CLI」；
確認視窗會顯示目標版本及安裝路徑。確認後背景安裝指定版本，再以實際 CLI 的 `--version` 驗證結果。
原生獨立安裝或無法確認來源的安裝只提供手動更新說明，不嘗試覆蓋。

更新期間會顯示安裝／版本驗證進度，重新進入頁面會在同一瀏覽器分頁內恢復追蹤。
完成後自動重新檢查登入狀態與刷新模型清單；模型連線測試仍由使用者自行點擊。
更新失敗、逾時或 API 重啟後，先重新檢查實際版本，不會自動重送安裝。
錯誤會區分網路、檔案占用／權限與 Node.js 版本問題，不顯示 npm 原始輸出。

正在執行的任務、討論、登入與 probe 會阻擋更新；更新時 Worker 保留排隊任務，暫停領取新任務。
請先結束自己另外開啟的 CLI 終端，避免 Windows 鎖住執行檔。
首次套用這次程式變更，需重啟 API 與 Worker；兩者須使用相同 `DevFlow:CliControlRoot`。
一般 npm CLI 更新完成後，API 與 Worker 會重新辨識 CLI 路徑，不需再次重啟。

## 討論、規則與 AI 驗收

登錄專案的「選擇資料夾」預設開啟 Windows 原生資料夾選擇器，選好後自動填入完整路徑，取消則保留原本輸入。API 需在目前登入的 Windows 桌面執行；選擇器使用獨立 STA 執行緒及目前前景視窗作為擁有者，不透過 PowerShell 開啟。關閉頁面或取消請求會關閉原生視窗，三分鐘未完成會逾時。也可明確切換「改用頁面瀏覽」，瀏覽 API 所在電腦的本機磁碟與資料夾。

- 左側「討論」改為聊天介面：選專案後直接輸入問題，第一則問題的首行會擷取為簡短名稱，不額外呼叫模型；點擊對話標題可重新命名。左側可搜尋與切換既有對話。
- 輸入框旁的模型按鈕依序選 AI 工具、模型及推理程度，可在同一對話隨時切換，從下一則訊息生效。每則回答保留當時的模型與推理設定；跨工具會帶入完整已保存對話。瀏覽器會記住各對話及專案最後選擇。
- Enter 傳送、Shift＋Enter 換行，中文輸入法選字的 Enter 不會送出。送出後由 API 在背景處理，離開頁面不會中斷；停止按鈕只會取消指定的執行，完成清理後才接受下一則。失敗或停止會保留使用者訊息，不自動重送。
- Antigravity、Codex、Claude、Gemini 的助手文字依各原生協定逐步顯示；工具輸出與推理日誌不會送進聊天預覽。停止時若已有部分回覆，會保存並標示「回覆已停止」。
- 規則自動沿用專案預設快照，與任務草稿收在右上「任務草稿與規則」中，需要時再展開。建立對話不呼叫模型；送出訊息與整理成任務草稿會使用所選 CLI 的模型額度。
- 草稿可編輯名稱、需求、驗收條件、規則與流程；待釐清問題需先確認處理方式。草稿轉任務預設不自動規劃或實作，來源討論與任務互相保留連結。重送同一草稿不會重複建立任務。
- 左側「規則庫」提供新增、編輯與封存，以及各專案的預選規則。任務與討論保存規則版本快照，規則庫後續修改不影響既有任務。
- 新增任務可填本次專屬規則、選擇 TDD 或一般實作，並設定允許編輯的路徑。檔案使用 Repository 相對路徑；資料夾以 `/` 結尾，不使用萬用字元。留空代表整個 Repository。
- 新任務使用可排序的流程卡片，預設為「後端 API → 前端實作 → 整合測試」。可拖曳或使用上下按鈕排序，在選取步驟後插入實作、AI 審查、整合測試或人工確認，最多 20 步且至少保留一個實作步驟。每個 AI 步驟可獨立選工具、模型與推理程度，並填工作內容與完成條件；實作可設定單一步驟允許修改的路徑，全域路徑與 TDD 限制仍同時生效。整體規劃／核准與最終人工驗收是固定的前後關卡；可在建立時省略 AI 規劃。Antigravity 尚未接入，不能選用。
- 流程範本儲存在 SQLite，可跨重啟使用；同名儲存會更新範本，套用會產生新步驟 ID，既有任務不受範本修改影響。已完成或執行中的步驟鎖定，只能修改尚未開始的部分，保存時會檢查任務版本，避免覆蓋執行中的進度。
- 各步驟在同一個 Run 的 worktree 依序執行並保存 commit，後一步直接使用前一步成果。人工確認或設定「完成後等我確認」會保存進度並暫停；點選「確認並繼續流程」後建立新 Run，從上一個完成步驟的 commit 接續，保留最初基底以檢查完整差異。失敗不會自動呼叫模型重試，需先檢查紀錄並提供重試指示；重試從失敗步驟繼續，未通過驗證的未提交變更保留在舊 worktree，不會自動帶入。人工退回最終成果後，則從退回的成果 commit 重新走流程。
- 整合測試使用專案登錄的 `dotnet test` 參數，尚未支援設定 npm 測試指令。每一步的模型輸出與測試證據分開保存。AI 審查未通過時停止後續步驟，可調整未完成的步驟再重試；不自動替你新增修正步驟。舊任務保留原本零至兩次 AI 驗收與自動修正機制。
- 模型欄位提供下拉選擇、CLI 預設與自訂模型 ID。Codex 會從官方 CLI app-server 讀取模型目錄並短暫快取；Antigravity 從 `agy models` 讀取模型清單；Claude 顯示 CLI 別名或設定的模型選項。清單不代表帳號權限已驗證。
- 各階段模型旁可設定推理程度，包含專案預設、討論、規劃、實作、AI 驗收與連線測試。Codex 從模型目錄讀取每個模型支援的等級，透過單次執行的 `model_reasoning_effort` 設定傳入；Claude 使用 `--effort`，實際等級仍可能受模型、CLI 版本及組織限制調整。Antigravity 介面依 CLI 目錄將模型與深度分開顯示，選擇深度會對應到實際存在的完整模型 ID，不另外疊加推理覆寫；自訂或無法辨識的模型保留原選項並隱藏深度欄位。
- 未指定模型／無推理能力資料時沿用 CLI 預設。切換模型會清除本次推理選擇，避免帶到不同模型；舊任務沒有此欄位時沿用 CLI 設定。設定與執行／驗收快照會保存推理程度，修改專案預設不會改寫既有任務。更新後需重啟 API 與 Worker。
- AI 連線頁會自動檢查登入狀態；登入流程結束後重新確認，已登入時隱藏登入控制。Antigravity 等 CLI 無法免額度判斷登入狀態時會標示「無法確認」，可手動重新檢查或登入。
- AI 驗收讀取確切 commit 的完整差異、核准計畫、規則及獨立測試摘要；報告與 CLI 輸出在執行紀錄中保留。修正使用新 Run，最終成果差異保留原始基底，涵蓋所有修正。

更新後需重新啟動 API 與 Worker；正式部署需先建置前端再建置 API。既有 SQLite 資料會保留，啟動時自動建立規則與討論資料表。
討論使用 API 所在主機的 CLI 與唯讀 worktree，不依賴 Worker；實作與 AI 驗收需要 Worker。API 中斷的討論會保留已送出的訊息，需明確重試，不會自動重送模型呼叫。
文字規則由模型理解與人工驗收；TDD 有測試證據檢查，允許編輯範圍由 Git 檔案差異檢查。範圍檢查不是作業系統的檔案存取隔離。

React + TypeScript + Vite。API 使用 .NET，AI 執行由 Worker 呼叫官方 CLI。

## 儲存空間管理

左側「儲存空間」顯示 API 實際使用的 SQLite 資料庫（含 WAL／SHM）、執行產物及工作副本路徑、檔案數與容量。容量為檔案內容大小，未包含來源 Repository 或共用 Git 物件；掃描無法完整讀取時會顯示部分容量。

可依 7／30／90／180 天或所有已結束任務產生清理預覽。保留天數依任務最後活動與執行完成時間計算；僅納入已合併或已取消、所有 Run 均已結束的任務。預覽五分鐘有效，每次最多確認 100 項。此版由使用者手動預覽與確認，不會自動清理。

確認時會重新核對任務版本與檔案清單。有未提交／未追蹤檔案、符號連結／junction、子模組或其他 Git Repository 的工作副本會保留。工作副本僅透過不含 force 的 `git worktree remove` 移除，保留 DevFlow 分支與成果 commit；不處理不符合設定目錄或無法歸屬到任務的資料。

清理執行產物會保留各階段 `evidence.json`，因此任務中的測試摘要仍可查看；SQLite 內的任務、規則、討論與 AI／人工驗收紀錄保留。原始日誌與 TRX 報告刪除後無法由 DevFlow 還原。清理結果逐項顯示，並寫入任務事件；中斷連線後已確認的清理仍會完成結果紀錄。

## 開發啟動

建議在 DevFlow **專案根目錄**執行 `npm run dev`，一次啟動 React、API 與 Worker。首次使用先在 `frontend` 執行 `npm ci`。根目錄啟動器不需另裝套件；會先建置 .NET 後端，核對資料庫與 Worker 回報後再顯示就緒網址。僅啟動後端可用 `npm run dev:backend`。

預設資料固定使用 `backend/src/DevFlow.Api/.data/devflow.db`，不受 API／Worker 各自的工作目錄影響；原有任務資料不會被搬移或重建。`DevFlow__DatabasePath`、`DevFlow__ArtifactsRoot`、`DevFlow__WorktreeRoot`、`DevFlow__CliControlRoot` 的明確設定仍優先；自訂路徑建議填絕對路徑。

右上角會顯示同一份資料庫的 Worker 是否連線。Worker 每 3 秒回報，超過 15 秒沒有回報視為離線；排隊頁會直接提示啟動方式。舊版 API 沒有狀態接口時顯示狀態未知，需先停止舊服務再用新啟動器開啟。已啟動的桌面版不受影響。

以下是仍可使用的分別啟動方式：

需要 Node.js 24.15 以上（或 26 以上）與 .NET 10 SDK。
在三個 PowerShell 視窗分別執行：

```powershell
# 視窗 1：API
cd C:\Gary\SideProject\DevFlow\backend
dotnet run --project src\DevFlow.Api
```

```powershell
# 視窗 2：Worker
cd C:\Gary\SideProject\DevFlow\backend
dotnet run --project src\DevFlow.Worker
```

```powershell
# 視窗 3：React（首次啟動或套件有更新時先 npm ci）
cd C:\Gary\SideProject\DevFlow\frontend
npm ci
npm run dev
```

開啟 http://127.0.0.1:5173。Vite 代理 `/api` 至 http://127.0.0.1:5180。
API／Worker 需使用相同資料庫、Artifact 路徑與 Windows 使用者。
如需改變 API 埠，在前端視窗設定 `$env:DEVFLOW_API_URL='http://127.0.0.1:其他埠'`。
官方登入與 probe 維持本機來源檢查，開發代理只重寫符合 Vite 同源位址的 Origin。

## 功能

| 畫面 | 功能 |
| --- | --- |
| 總覽 | 任務統計、待人工處理事項、最近任務 |
| 任務工作台 | 專案／狀態篩選、搜尋、建立任務、指定規劃／實作 AI 與模型 |
| 專案 | 登錄 Repository、基底分支、測試參數、AI 預設 |
| AI 連線 | Codex、Antigravity、Claude Code 安裝與登入狀態、官方登入／取消、診斷、模型連線測試 |
| 計畫 | 編輯、歷史版本、AI 規劃、指定版本核准 |
| 執行 | Run 切換、Worktree／commit、TDD 階段證據、事件、Artifact 分頁 |
| 審核 | diff、核准／退回、修正重試、本地合併預覽與歷史、中斷核對 |

每五秒輪詢；頁面隱藏時暫停。CLI log 在階段結束後保存。
React state 保留輪詢與頁籤切換中的編輯；離開任務會清除未保存的草稿。
計畫保存使用 expectedVersion，衝突會保留輸入，不自動重送。
歷史計畫唯讀；未保存的計畫不能核准。審核需先讀取 diff，傳送精確 Run、commit 與版本。
合併先顯示目標 HEAD，只做本地 fast-forward，不推送遠端。
Artifact 使用伺服器游標及文字顯示；較晚完成的旧請求會被丟棄。

首頁載入與輪詢不呼叫模型。自動規劃、核准實作及明確按下連線測試可能使用額度。
Claude 可先保存備用設定；憑證由官方 CLI 管理。

Codex 推理選單顯示低（low）、中（medium）、高（high）、極高（xhigh）、Ultra（ultra），
依所選模型回傳的能力縮減選項。若 CLI 目前預設模型缺少能力資料，允許手動指定這五項，
並標示支援狀態待 CLI 驗證。CLI 預設選項仍可保留原設定；連線測試才會實際驗證選定組合。

模型選單依可解析的版本號由新到舊排列（例如 GPT 6.1 在 GPT 6、GPT 5.6 之前），
同版本保留 CLI 目錄順序；未標版本的別名／自訂 ID 放在版本模型之後。
這是版本排序，不是模型發布日期或能力排名。CLI 預設選項固定置頂，自訂輸入入口置底。
目前設定中的模型若未提供目錄能力資料，畫面會顯示提示；已登入不代表指定模型可執行。

## Antigravity CLI

新任務改用 `Antigravity CLI`，執行檔是 `agy`，不是 Antigravity 編輯器的 `antigravity` 啟動指令。
依 [官方說明](https://antigravity.google/docs/getting-started?tab=cli) 安裝後，在終端執行 `agy` 完成登入，輸入 `/exit` 離開，再重新啟動 DevFlow API 與 Worker。
若執行檔未加入 PATH，可對 API 與 Worker 同時設定 `DevFlow__AntigravityExecutable` 為原生執行檔完整路徑；可選擇用 `DevFlow:Models:Antigravity` 設定模型 ID。
AI 連線頁會讀取 `agy models`；讀取失敗時可保留 CLI 預設或輸入實際模型 ID。不能直接沿用 Gemini CLI 的 `pro`、`flash` 等別名。
版本檢查僅讀取 `agy --version`，更新可在終端執行 `agy update` 或使用官方安裝方式。

規劃／討論／AI 審查使用 `--mode plan`，實作使用 `--mode accept-edits`，均啟用 `--sandbox`。
透過 stdin 傳送一則 stream-json 訊息並關閉輸入，僅接受退出碼 0 且終端 result 為 SUCCESS 的非空回覆。
不自動跳過權限。Antigravity 的 shell 工具預設可能因無人值守而被拒絕；如需執行測試，請依官方 permissions 文件設定必要的命令授權。DevFlow 仍會獨立驗證工作區與測試結果。

舊 Gemini 任務與專案預設保留原始 provider 與模型，避免靜默切換工具；要改用 Antigravity，請在專案或新任務設定中重新選擇。舊任務執行仍需原 Gemini CLI。

Antigravity 模型分組需同時符合模型 ID 的深度後綴與顯示名稱中的深度標籤；只提供目錄中已存在的組合，沒有目錄時不推測可用深度。既有額外推理覆寫會明確提示，可手動改用模型內建深度，不自動改寫已保存設定。

## 工具分類與單次確認

任務與討論共用工具分類、風險原因與允許規則。一般讀取以綠色標示；敏感讀取、寫入、未知操作以橘色標示；刪除與高影響 Git 操作以紅色標示。標籤同時包含文字與圖示，不只依賴顏色。

- 一般讀取：明確位於本次工作副本內的已辨識程式碼、一般開發文件、目錄與檔名查詢。可單次允許，或允許同一任務／對話內後續的一般讀取，涵蓋不同檔案與工具。規則可指定全部 CLI 或目前 CLI。
- 敏感讀取：資料庫工具與檔案、SQL／備份、資料與設定檔、常見帳密／憑證／個資路徑、專案外讀取。逐次確認，不提供批次或永久允許。
- 寫入、刪除、未知工具、未支援語法的 Shell 指令、額外權限與無法確認排除機敏資料的內容搜尋：不能批次放行。能辨識的刪除、資料庫修改、強制 Git 操作會提供較具體的風險標籤。

後端支援完整參數的唯讀指令辨識，不執行指令來判定：`Get-ChildItem` 列目錄、`Get-Content` 程式碼讀取與受限編碼參數、`Select-String -Path ... -Pattern ...`、`Test-Path`／`Get-Item` 檔案資訊、對程式碼的 `Get-FileHash`、`rg` 搜尋／檔名查詢，以及受限的 `git status`／`git diff`／分支清單／追蹤檔名／目前提交識別。`git`、`dotnet`、`node`、`npm`、`rg` 的單純 `--version` 也歸一般查詢。只有路徑範圍、權限與所有參數皆通過檢查，才可套用本次任務／對話的一般讀取規則。

`rg -n --glob '*.cs' pattern src` 支援限定單一程式碼副檔名的遞迴搜尋：逐一檢查實際匹配檔名與敏感路徑，遇到符號連結或超過 5000 個檔案／目錄就改為單次確認；不允許 `--pre`、`--follow`、任意 glob 或多組篩選。單純列目錄的遞迴檢查另限 2000 個子目錄。

唯讀管線只支援已核可的一般讀取來源，接固定語法的 `Where-Object` 屬性／比較運算子／字面值篩選、`Select-Object` 已支援欄位與筆數、`Sort-Object` 排序及 `Measure-Object` 統計。例如 `Get-ChildItem src | Where-Object { $_.Extension -eq '.cs' } | Select-Object -ExpandProperty FullName`。不能透過篩選將原本敏感的讀取升級為一般讀取；任意腳本、計算欄位、方法呼叫、未知屬性、指令串接、變數展開與直譯器包裝仍需確認。

建置／測試／執行腳本、套件安裝與設定變更、網路下載／傳送／發布、Git 修改與檔案新增／覆寫／搬移／重新命名均有具體敏感標籤，仍不批次允許。輸出重新導向與 `Out-File` 也視為寫入。Git 歷史訊息／內容、套件設定與資料庫結構／實際資料都需單次確認。未支援參數會盡量指出參數名稱，但不把參數內的密碼值放進判定原因。

例如 `Get-ChildItem -Force` 歸一般目錄讀取；`Select-String -Path "backend\**" -Pattern "salDispatchList|Dispatch|NET6NBS" -CaseSensitive:$false` 會標示「敏感讀取：搜尋／讀取範圍過廣」，因為範圍包含設定或資料檔。`backend\*.cs` 這類只有最後檔名使用萬用字元的來源搜尋，會檢查當前實際匹配的檔名（最多 2000 個檔案），遇到 `secrets.cs` 等敏感名稱也不批次允許。`git diff` 需關閉 ext-diff／textconv，查看內容時另需限定明確程式碼檔案；未限定內容範圍會歸敏感讀取。

分類依工具、參數、目標路徑、已知檔案類型與常見敏感名稱判斷，並排除符號連結／目錄連接；不讀取檔案內容來推斷是否含秘密，也不是資料外洩偵測系統。一般原始碼中若硬編碼了秘密，不能只靠副檔名自動識別。網站顯示參數時遮蔽已知帳密欄位與常見密碼參數；核准仍對應原始參數。

所有新批次規則僅限同一任務或對話，不開放跨任務永久允許。舊的精確、指令前綴、路徑與專案永久規則保留紀錄，但不再提供自動放行，可停用或刪除。後端在新請求比對與回覆時重新分類，直接呼叫 API 也不能建立敏感批次或永久授權。停用／刪除只影響後續請求，不撤回已開始的操作。

底層仍使用各 CLI 的原生機制：Antigravity 的 `PreToolUse` hook、Codex app-server 的單次 accept／decline、Claude stdio can_use_tool、Gemini ACP allow_once／reject_once。**分類管控的是進入 DevFlow 的工具確認請求；CLI 依自身政策直接執行、未提出確認的操作不會由這個頁面攔截。** 不改寫各 CLI 全域設定，也不取代原生沙盒與限制。若原生請求最小只能授權整個回合（例如 Codex permissions grant），會拒絕該擴權，不將其誤標為單次允許；請改用具體工具或指令的單次請求。Antigravity 的專案內讀取也會經過 hook 交給 DevFlow 分類，不再因為在專案內就直接略過。

工具確認區限制高度並提供捲動；待確認項目優先排列，歷史參數預設收合。任務請求經共用 SQLite 在 API／Worker 間交換，討論請求綁定目前操作；最長等待兩分鐘。取消、停止、逾時、重複或過期回覆不會取得授權。完整計畫的人工核准與工具確認獨立。規劃／討論仍禁止直接寫入與刪除。

Antigravity hook 使用目前使用者專屬的本機 Named Pipe，完成後還原 `.agents/hooks.json`；單次決定保存於 artifacts 的 `permission-decisions.jsonl`。Codex 協定已核對本機 0.155.1 schema；Claude／Gemini 本機未安裝，已用協定測試替身驗證，仍需實際帳號端到端測試。

## 任務執行動態

任務詳情頁會顯示目前階段、執行時間、程序狀態與最近輸出時間；討論中的 AI 回覆也有相同狀態卡。任務 Worker 每 5 秒保存最新回報，網站隨既有任務查詢更新。回報超過 20 秒未更新或讀取失敗時，會顯示「執行回報中斷」，不會將沒有輸出當成已停止或已完成。排隊、等待步驟核准與等待工具確認會分別顯示。

只保存最近 12 筆階段與程序活動及輸出字元數，不會將工具輸出或模型思考內容放進動態卡，也不會在事件紀錄持續新增心跳訊息。啟用這項功能需要重新啟動 API 與 Worker，並重新整理網頁；既有執行中的舊程序不會補出新回報。

## 從討論到任務，以及失敗後繼續

討論草稿先進入可編輯的摘要確認頁，確認需求、驗收條件與未決定事項的處理方式後，再設定流程。問題的處理方式會一併保存到任務需求，討論轉入的任務仍預設不自動執行。

建立任務可選 API 先行、前端先行、API 專用及既有範本；套用內建範本會保留同名角色的模型選擇。成功建立後可在目前瀏覽器記住每個專案的流程順序、模型與推理設定；不記住任務專屬指示、驗收條件或修改路徑。新任務與套用範本會產生新的步驟 ID。命名範本仍可透過既有「儲存範本」保存在 API 資料庫。

執行失敗會提供登入、模型、權限、額度、連線或測試的對應處理建議。無法辨識時會明確保留未知分類。更換模型只保存設定，查詢重試預覽只讀取資料，兩者都不會自動呼叫模型。最近一次討論的 artifacts 也能從處理建議卡開啟。

重試前會核對最新任務版本並列出起始成果、保留步驟與重新執行範圍。「接續既有成果」在多步驟任務保留已完成步驟，從失敗步驟的開頭重跑；「從原始基底全部重做」清除新一輪的完成步驟，重新使用原始實作基底。兩種方式都保留既有執行紀錄與 artifacts，並且需要使用者明確點擊開始。預覽後任務版本改變，送出會被拒絕並要求重新讀取。

已取消的任務可按詳情頁上方「重新開始」。必須等舊執行收尾完成才可點擊，網站仍會更新停止狀態。啟用 AI 規劃的任務會重新排隊規劃，新計畫需要重新核准；省略 AI 規劃的任務回到計畫確認，缺少有效計畫則回到待規劃。需求、模型、規則、舊計畫版本與執行紀錄保留，但清除實作接續狀態與完成步驟，後續實作會從頭執行。重複點擊或舊版本請求不會重複排隊。

工具活動摘要依實際協定事件產生：Codex JSONL 與 Antigravity stream-json 可顯示讀檔、搜尋、命令、測試或檔案變更等活動。不會解析或展示模型私有思考；沒有提供細節的 CLI 仍以執行階段、程序與輸出時間回報，不推測工作內容。

AI 規劃不只檢查 CLI 的退出碼。Antigravity 即使回傳 SUCCESS，只要規劃的終端結果包含 denied_actions，也會標為規劃未完成；一般討論仍允許提供有用的受限回覆。明確只有「正在分析／讀取」的進度公告不能發佈為計畫，既有這類內容仍擋住核准，計畫編輯區不再插入警示段落。這個檢查不替代人工檢視計畫完整性。
